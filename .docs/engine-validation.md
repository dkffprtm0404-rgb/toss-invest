Java 17에서 전체 테스트 22개와 실행 JAR 빌드가 통과했다. 저장소 CSV의 200종목을 각각 두 번 실행했을 때 결과 JSON이 일치했다. 이 결과는 기존 동작의 재현성을 확인한 것이며, 매매 정책과 성과 지표가 새 기획서에 모두 적합하다는 뜻은 아니다.

## 검증 환경과 실행 방법

현재 환경에서는 기본 Gradle 실행이 Java 8을 사용해 Spring Boot 플러그인 로딩에 실패했다. 아래 명령에서만 Java 17 경로를 지정하여 컴파일과 테스트를 수행했다. 시스템 Java 설정은 변경하지 않았다.

프로젝트 루트의 PowerShell에서 실행한다.

```powershell
$env:JAVA_HOME = 'C:/Program Files/Java/jdk-17'
.\gradlew.bat test bootJar --offline --console=plain
```

`--offline`은 의존성이 로컬에 준비된 검증 환경 기준이다. 새 환경에서는 의존성 설치 후 실행해야 한다. 테스트를 다시 실제 실행하려면 명령에 `--rerun-tasks`를 추가할 수 있다.

기존 `contextLoads`는 임시 메모리 DB를 사용하도록 분리했다. 모의매매·스캘핑 스케줄러는 테스트 대역으로 대체했다. 스케줄러의 실동작과 외부 API 정상 연결은 이번 테스트의 검증 범위에 포함되지 않는다.

## 확인한 동작과 설계에 미치는 영향

### 당일 종가 판단과 같은 가격 체결

엔진은 `closes[i]`로 조건을 판단하고 같은 가격으로 진입·청산한다. 장중 저가가 손절선을 밑돌아도 종가가 회복하면 손절하지 않는다. 테스트에서 매수가 100, 다음 날 저가 90, 종가 99인 경우 청산 사유는 손절이 아닌 데이터 종료였다.

사용자 확인에 따라 새 전략 명세에서는 당일 종가와 다음 거래일 시가를 선택할 수 있게 한다. 손절·익절을 포함한 모든 매수·매도에 같은 실행 방식을 적용한다. 아직 운영 엔진에는 구현하지 않았다.

### 기존 점수제의 매수 조건

골든크로스만으로는 기본 매수 임계값 5점에 미달한다. 거래량 동반 돌파 3점과 변동성 목표가 도달 2점을 함께 만족하면 5점으로 진입한다. 평균 거래량의 1.5배 경계, 거래대금 30억 이상, RSI 80 미만, 시가 갭상승 10% 미만과 당일 상승률 20% 미만을 테스트로 확인했다.

이는 기존 기본 전략에 대한 확인이다. 자연어로 입력한 단일 조건 전략에 이 점수와 필터를 자동 적용하는 것은 별도의 동작이므로 새 명세에서 구분해야 한다.

### 보유기간과 같은 봉 재진입

기존 백테스트는 매수 봉을 0으로 두고 봉 인덱스 차이를 보유일수로 사용한다. 기준이 5일이면 6번째 후속 봉에서, 트레일링이 활성화되지 않았을 때 시간 청산한다. 청산한 봉에서 매수 조건을 다시 검사하므로 같은 봉에 재진입할 수 있다. 마지막 봉에서도 신규 진입 후 즉시 `END_OF_DATA`로 종료할 수 있다.

모의매매의 `PaperTradingService`는 `LocalDate` 차이를 사용하므로 주말·휴일을 포함한다. 백테스트와 모의매매의 보유기간 의미를 맞추려면 별도 변경이 필요하다. 실제 거래일 캘린더와 거래 정지일을 어떻게 셀지는 설계에서 확인해야 한다.

사용자는 시간 청산의 '기준일 초과 + 트레일링 미활성' 조건을 유지하기로 했다. 문구는 강제 상한을 뜻하는 '최대 보유기간'보다 '시간 청산 기준 거래일 수'가 정확하다.

### 트레일링 규칙의 문서 불일치

현재 코드에서 시작 기준이 3%라면 최고수익률 3%에서 보호선 0%, 6%에서 3%, 9%에서 6%가 된다. 테스트에서도 최고수익률 6% 후 2%로 하락할 때 트레일링 청산이 재현됐다.

기존 `trading-rules.md` 3.2의 표는 시작 기준에 5%p를 더한 구간을 사용하고, 바로 아래 설명도 다른 수치를 포함한다. 백테스트와 매도 신호 서비스 코드는 같은 계산식을 사용하지만 문서와 일치하지 않는다. 사용자 확인에 따라 기존 코드의 3%p 간격과 보유기간 3거래일 초과 시 시작 기준을 1.5%로 낮추는 규칙을 모두 유지한다. 이 결정은 새 전략 명세에 기록했으며 기존 규칙 문서의 표는 이번 작업에서 수정하지 않았다.

### 거래 중단 후 재개 조건

최근 20건의 승률이 35% 미만이면 새 진입을 막는다. 단일 종목 백테스트에서는 진입을 막은 후 종료 거래 목록이 바뀌지 않아, 기다리는 것만으로는 최근 20건의 승률이 회복되지 않는다. 강제로 손실을 발생시키는 시나리오에서 20건 이후 장기간 재진입하지 않는 동작을 재현했다.

이는 기존 문서의 '승률 회복 후 재개'를 자동으로 만족할 수 없는 구조다. 재개 방식이나 새 사용자 전략에 이 규칙을 적용할지는 아직 확정하지 않았다.

### 지표와 집계 방식

- EMA는 초기 SMA 이후 지수 가중치를 적용한다. 검사한 과거 구간의 EMA·RSI·거래대금·돌파 기준은 미래 봉을 추가해도 바뀌지 않았다. 전체 시스템에서 미래 데이터 사용 가능성을 모두 배제했다는 의미는 아니다.
- RSI는 최근 구간의 평균 상승·하락으로 계산하며 Wilder 누적 평활 방식은 아니다. 모든 가격이 같은 구간에서는 현재 구현이 RSI 100을 반환한다.
- 누적수익률은 거래 수익률의 단순 합이다. +10%, -10% 거래의 결과는 0이며 계좌 복리 결과와 다르다.
- 낙폭은 거래 수익률의 누적 합 곡선에서 구한다. 일별 계좌 평가자산의 MDD와 다르다.
- 샤프는 거래별 평균/표준편차를 사용하며 연율화하지 않는다. 표준편차가 0이면 0을 반환한다.
- Profit Factor는 총이익/총손실 비율이다. 손실이 전혀 없고 이익만 있으면 현재 구현은 3으로 치환한다. 이는 측정값이 아닌 예외 처리다.
- 엔진 결과에 초기 자금, 수량, 거래 비용과 계좌 평가자산 곡선이 반영되지 않는다. 해당 계산을 추가하기 전까지 결과 설명에서 그 한계를 표시해야 한다.
