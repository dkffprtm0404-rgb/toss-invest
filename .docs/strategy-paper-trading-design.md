# 전략별 페이퍼 트레이딩 — 8단계 A 설계

작성일: 2026-09-28  
기준: [기획서](project-plan.md) FR-06, [전략 명세](strategy-spec.md), [사용자 전략 백테스트](user-strategy-backtest.md).

**상태:** 사용자는 A안(단일 종목 전략부터 완성 후 포트폴리오·조합으로 확장)을 선택하고 2026-09-28 설계 진행을 승인했다. 중지는 추천한 신규 매수 중단·기존 청산 관리 방식으로 확정했다. 구현 및 검증 상태는 [구현 기록](strategy-paper-trading-plan.md)을 따른다.

## 1. 목표와 범위

저장한 단일 종목 전략의 특정 버전을 선택하고, 국내 주식 한 종목에 독립된 가상 계좌를 만들어 이후 일봉에 따라 매매한다. 같은 종목을 여러 전략으로 실행해도 현금·포지션·주문·거래 이력이 섞이지 않아야 한다.

- 지원: `schemaVersion` 1·2, 국내 주식 일봉, 매수 포지션 한 개, 정수 수량, 전량 청산.
- 사용자 흐름: 저장 버전 선택 → 종목·자금·비용 입력 → 시작 → 처리 현황·손익 조회 → 중지.
- 저장 전략 수정은 이미 시작한 실행에 반영하지 않는다. 새 버전 적용은 새 실행으로 한다.
- 형식 3 포트폴리오와 형식 4 조합은 화면과 서버에서 미지원 사유를 표시한다.
- 기존 점수제 페이퍼 트레이딩은 기존 기능으로 유지한다. 사용자 전략에 기본 점수제 필터나 거래 중단 규칙을 추가하지 않는다.
- 실제 주문, AI 호출, 포트폴리오·조합 전략 실행은 이번 범위에 포함하지 않는다.

## 2. 확인한 재사용 지점과 제약

- `StrategyEvaluator`: 일봉 진입·청산 조건, 손절·익절·보유 봉 수·트레일링·ATR 판단을 재사용한다.
- `SavedStrategyService`: 명시한 저장 버전 조회, 엄격한 전략 검증과 JSON 직렬화를 재사용한다.
- `PortfolioCalculations`: 정수 수량과 슬리피지·수수료 계산을 재사용한다.
- `MarketDataService`: 기존 시세 조회 연결을 사용한다. 별도 LLM이나 새 시세 제공업체를 도입하지 않는다.
- `PaperPosition`에는 전략·수량·현금 필드가 없고 기존 서비스는 `TradeSignalService`를 사용한다. 사용자 전략 계좌는 별도 테이블과 서비스로 추가한다.
- `CandleCollectionService`는 기존 날짜의 값을 덮어쓰지 않고 최근 개수 밖의 캔들을 정리한다. 공용 캐시만으로 장기 실행의 EMA 초기값·ATR·보유기간을 복구하지 않는다.
- 단일 종목 백테스트는 자금·비용을 모델링하지 않는다. 페이퍼 계좌 수익률을 기존 거래 수익률 합계와 같은 지표로 표시하지 않는다.

기존 페이퍼 테이블 확장은 점수제와 사용자 전략의 규칙·계좌가 섞이기 쉽다. 매번 백테스트를 다시 실행해 결과를 덮어쓰는 방식은 중지·대기 주문·데이터 변경을 처리하기 어렵다. 따라서 공통 판정기를 사용하는 별도 영속 실행 서비스를 제안한다.

## 3. 시작 입력과 실행 단위

필수 입력:

- 저장 전략 ID와 버전.
- 국내 종목 코드와 시장 확인 정보. 단순히 코드 형식이 맞는다는 이유만으로 국내 주식으로 확정하지 않는다.
- `executionMode`: `SAME_DAY_CLOSE` 또는 `NEXT_DAY_OPEN`.
- `initialCapital`: 초기자금(원).
- `allocationRate`: 진입할 때 가용 현금 중 사용할 비율, 0 초과·1 이하.
- `commissionRate`, `taxRate`, `slippageRate`: 비용률. 미적용도 0을 명시한다.
- `requestId`: 시작 요청 재시도에 사용하는 식별자. 화면에서 생성하고 같은 요청의 재시도에는 재사용한다.

서버가 금액·비율·체결 방식을 임의로 채우지 않는다. 입력 한도와 소수 정밀도는 기존 계좌형 백테스트의 검증 범위를 기준으로 정의한다. 화면은 퍼센트, API는 소수 비율임을 명시한다.

동일 전략 ID·종목의 미종료 실행은 하나만 허용하는 안을 제안한다. 버전을 바꿔 중복 실행 제한을 우회하지 않는다. 다른 전략의 같은 종목 실행과 같은 전략의 다른 종목 실행은 허용한다. 같은 `requestId`·같은 입력은 기존 실행을 반환하고, 같은 키·다른 입력은 충돌로 거절한다.

시작 요청은 미래 방향의 실행을 만든다. 최초 매매 판단일은 생성일 다음 한국 날짜부터로 한다. 그 이전 일봉은 지표 준비에만 사용하며 과거 거래를 소급 생성하지 않는다. 화면에 최초 판단 가능일을 표시한다.

## 4. 일봉 공급과 반영 시각

첫 버전은 확정 일봉을 순서대로 처리하는 모의매매다. 장중 실시간 주문 체결을 의미하지 않는다.

- 안전한 날짜 경계로 한국 날짜가 오늘보다 이전인 일봉만 처리한다. 제공업체 응답에는 일봉 확정 표시가 없으므로 당일 봉을 시간만 보고 확정으로 간주하지 않는다.
- 자동 작업은 일봉을 정기 조회하고, 화면의 수동 갱신도 같은 처리 경로를 사용한다. 새 봉이 없으면 거래를 만들지 않는다.
- API 수신 시각, 신호 기준 시각, 가상 체결 기준 시각, 서버 반영 시각을 구분해 기록한다. 최소 하루 늦게 반영될 수 있다는 점을 시작 화면과 결과 화면에 표시한다.
- 휴일·거래정지·데이터 누락을 날짜만으로 구별했다고 주장하지 않는다. 마지막 데이터 날짜와 `WAITING_DATA` 사유를 제공하고 가격이나 거래일을 임의 생성하지 않는다.
- 최초 실행의 준비 일봉과 이후 사용한 일봉은 실행 전용으로 저장한다. 공용 캐시 정리 후에도 같은 이력으로 지표를 복원할 수 있어야 한다.
- OHLCV·일자·종목·통화·중복 날짜를 검증한다. 미완성·잘못된 봉을 0이나 이전 가격으로 보정하지 않는다.
- 이미 사용한 날짜의 다른 가격이 들어오면 원본을 덮어쓰지 않고 데이터 변경 오류로 표시한다. 수정주가 변경·분할 등을 자동으로 포지션에 적용하는 기능은 포함하지 않는다.
- 원격 데이터에 실패하면 실패 시각과 마지막 성공 데이터 날짜를 보존한다. 조회 화면은 저장된 계좌와 이력을 계속 제공한다.

수집은 계좌 잠금 밖에서 수행한다. 처리 시 다시 실행 상태와 마지막 처리 날짜를 확인한다. 준비 이력이 부족한 실행은 `INSUFFICIENT_DATA`로 표시하며, 나중에 준비가 충족되기 전까지 매수하지 않는다. 기존 OR 조건의 부분 준비 의미도 유지한다.

## 5. 판단·체결·회계

- `SAME_DAY_CLOSE`: 해당 일봉 종가로 판단하고 같은 종가에 슬리피지를 반영한 가상 가격으로 체결한다. 사후 종가 체결 가정임을 표시한다.
- `NEXT_DAY_OPEN`: 종가에서 만든 대기 주문을 다음 저장 일봉 시가 기준으로 체결한다. 다음 봉의 종가로 주문 방향·수량을 미리 결정하지 않는다. 해당 봉이 확정된 뒤 반영된다는 점은 별도 처리 시각으로 드러낸다.
- 매수 체결 시점의 가용 현금 × 배분 비율을 예산으로 삼고 수수료를 포함한 주당 필요 현금으로 나눈 정수 수량을 사용한다. 1주도 살 수 없으면 `INSUFFICIENT_CASH`를 기록하고 포지션을 만들지 않는다.
- 추가 매수·분할 매도는 하지 않는다. 매도는 전량이며 수수료·매도세를 현금에 반영한다.
- 가격 기반 위험 판단의 기준 매수가는 실제 가상 체결가(슬리피지 포함), 수수료·세금은 계좌 손익에 반영한다. 비용 때문에 비용 0의 백테스트와 위험 신호가 달라질 수 있음을 표시한다.
- 보유기간은 매수 봉을 0으로 한 처리 일봉 수다. 달력 일수를 사용하지 않는다.
- 같은 종가에서 매도 후 재매수하지 않는다. 다음 시가에 청산했다면 그날 종가의 새 진입 신호는 허용한다.
- 진입 전 ATR, 보유 중 최고가와 일봉 이력을 보존해 재시작 전후 판단을 유지한다.
- 거래량 0인 봉에서 체결해야 하면 거래·잔고·처리 위치를 변경하지 않고 오류를 표시한다. 기존 백테스트 계약처럼 조용히 체결하거나 임의로 다음 봉에 이월하지 않는다.
- 일봉 끝에 보유분이 있으면 평가손익으로 표시한다. 아직 다음 봉이 없는 주문은 대기 상태로 보존한다.

계좌는 초기자금, 현금, 보유 수량, 평균 매수가, 평가액, 실현·미실현 손익, 누적 비용, 계좌 수익률을 제공한다. 계좌 수익률은 `(현금 + 보유 평가액) / 초기자금 - 1`이다. 미실현 손익은 매수 수수료를 포함한 원가 대비 현재 평가액이며 아직 발생하지 않은 매도 비용을 차감하지 않는다. 일별 평가자산과 양수 비율의 최대 낙폭을 저장한다. 거래 단위 샤프를 계좌 샤프로 가져오지 않는다.

## 6. 중지 정책 — 신규 매수 중단 후 청산 관리

채택한 정책은 1번이다. 2·3번은 검토한 대안이며 이번 구현에 포함하지 않는다.

1. **추천: 신규 매수 중단 후 기존 청산 조건으로 관리.** 미체결 매수 주문은 취소하고, 포지션이 있으면 `STOPPING`에서 청산 판단을 계속한다. 포지션·매도 대기가 모두 없어지면 `STOPPED`가 된다. 청산 조건이 없는 전략은 자동 종료되지 않을 수 있음을 중지 전에 표시한다.
2. **전체 일시정지.** 매수·매도 판단과 체결을 중단하고 포지션을 보존한다. 이 경우 재개 시 정지 구간의 처리 정책까지 추가로 확정해야 한다.
3. **종료 청산.** 매수 대기를 취소하고 다음 체결 가능한 일봉에서 전량 청산한 뒤 종료한다. 다음 데이터가 없을 때는 청산 대기로 남는다.

선택에 관계없이 중지는 같은 실행의 처리와 직렬화한다. 이미 확정 저장한 체결을 되돌리지 않으며 중지 요청 시각과 취소·종료 사유를 기록한다. 중지 요청 후 새로 반영하는 미처리 과거 구간에서도 신규 매수는 허용하지 않는다.

중지 후 새 계좌 시작은 별도 실행을 만든다. 실행 중 전략 조건·자금·비용 수정은 제공하지 않는다.

## 7. 영속성·중복 방지·삭제

기존 파일 H2 설정을 사용하고 새 의존성을 추가하지 않는다.

- 실행: 전략 ID·버전·명세 스냅샷, 입력 설정, 시작·중지 시각, 상태, 현금·포지션·대기 주문, 마지막 처리 봉.
- 입력 봉: 실행별 JSON 체크포인트에 OHLCV를 보존하고 엔진에서 날짜 중복·수정 검사를 수행한다. 출처·최종 수신 시각·전체 입력 해시를 함께 저장한다.
- 처리 기록: 같은 체크포인트에 판단 근거·체결·비용·종가 평가자산을 저장한다. 실행 행 잠금과 마지막 처리 위치로 같은 일봉의 중복 처리를 방지한다.
- 운영 로그: 데이터 대기, 준비 부족, 실패, 중지·재시도 사유와 관측 시각.

실행별 DB 잠금과 트랜잭션으로 잔고·포지션·주문·처리 기록을 함께 반영한다. 오류 시 해당 처리 단위는 전부 롤백하고 오류 로그는 별도 저장한다. 수동·예약 호출이 겹치거나 요청을 재시도해도 같은 봉이 두 번 거래를 만들지 않아야 한다.

한 실행의 실패가 다른 전략 실행을 막지 않게 한다. 재시작 후 미종료 실행을 조회해 미처리 일봉부터 이어가며 전체 거래를 다시 생성하지 않는다.

삭제 정책 제안: 미종료 페이퍼 실행이 있는 전략 삭제는 409로 막는다. 종료된 실행은 명세 스냅샷으로 독립 조회되도록 원 전략 삭제 후에도 보존한다. 페이퍼 이력 삭제는 종료 실행에만 허용하고 기존 전략 삭제 확인 문구에도 보존 범위를 알린다. 원 전략 삭제에 따른 기존 백테스트·비교 이력 정책은 유지한다.

## 8. API·화면 제안

기존 `/api/paper` 점수제 API와 구분해 `/api/strategy-paper/runs`를 사용한다.

- `POST /api/strategy-paper/runs`: 입력 검증·버전 고정·실행 생성.
- `GET /api/strategy-paper/runs`: 페이지별 실행 목록, 전략·종목·상태 필터.
- `GET /api/strategy-paper/runs/{id}`: 당시 전략·실행 설정·계좌·상태·데이터 기준일.
- `POST /api/strategy-paper/runs/{id}/refresh`: 일봉 수집 및 미처리 데이터 반영.
- `POST /api/strategy-paper/runs/{id}/stop`: 확정할 중지 정책 적용.
- `GET /api/strategy-paper/runs/{id}/trades`, `/logs`, `/equity`: 페이지별 체결·로그·평가자산 조회.
- `DELETE /api/strategy-paper/runs/{id}`: 종료된 실행만 삭제.

잘못된 입력 400, 미존재 404, 중복 실행·상태 충돌 409를 구분한다. 원격 장애나 데이터 오류는 계좌의 마지막 성공 상태와 함께 설명한다. 전체 응답이나 화면에 접근 토큰을 포함하지 않는다.

저장 전략 상세에 ‘이 버전으로 모의매매’ 버튼을 추가한다. 기존 계좌·모의매매 화면에 사용자 전략 실행 목록과 상세 영역을 추가하고 시작 폼의 전략·버전을 명확히 표시한다. 형식 3·4는 지원 범위를 안내한다.

상세 화면은 실행 상태, 신규 매수 가능 여부, 마지막 데이터 날짜, 자금·비용, 포지션, 대기 주문, 실현·미실현 손익, 체결 근거, 운영 로그를 표시한다. 전략명이 HTML처럼 보여도 텍스트로 렌더링한다. 서버 실패 후 재시도할 때 시작 요청 식별자를 유지한다.

## 9. 구현 순서와 검증 기준

1. 입력·계좌·일봉별 처리 계약과 순수 계산 테스트.
2. 실행·봉·거래·로그 저장, 잠금·중복 방지·재시작 테스트.
3. 기존 시세 연결을 사용한 일봉 수집, 예약 실행과 API.
4. 저장 전략 연결 및 시작·중지·상세 화면.
5. 통합 회귀 검증과 사용 안내.

필수 검증:

- [ ] 같은 종목의 서로 다른 전략이 독립 현금·포지션·손익을 갖는다.
- [ ] 저장 전략 수정 후 실행 버전·판단이 유지된다.
- [ ] 비용 0·충분한 자금·같은 일봉에서 두 체결 모드의 판단·가격·사유가 기존 단일 종목 백테스트와 일치한다.
- [ ] 손절·익절·보유기간·추적손절·ATR·진입 준비 부족을 검증한다.
- [ ] 다음 시가 체결에서 미래 종가를 바꿔도 이미 결정한 주문 방향과 시가 수량이 바뀌지 않는다.
- [ ] 소수 정밀도·정수 수량·비용 차감·잔고 부족·거래 없음의 수치를 검증한다.
- [ ] 수동·예약 동시 호출과 중복 시작 요청에서 중복 매매·계좌가 없다.
- [ ] 파일 H2를 종료하고 다시 열어 대기 주문·포지션·최고가·일봉·잔고를 검증한다.
- [ ] 공용 캔들 삭제·정리 후에도 보존한 입력으로 동일한 실행 상태를 복구한다.
- [ ] 미완성 봉·미래 날짜·가격 오류·거래량 0·기존 봉 수정·시세 실패에서 잘못된 거래가 없다.
- [ ] 선택한 중지 정책의 대기 매수·보유 포지션·대기 매도·동시 처리 동작을 검증한다.
- [ ] 시작 가능일 전 거래가 발생하지 않고 실제 반영 시각이 체결 기준일과 구분된다.
- [ ] 브라우저에서 저장 버전 선택 → 시작 → 갱신 → 조회 → 중지와 오류 표시를 확인한다.
- [ ] 기존 전략 저장·삭제·백테스트·비교 테스트를 회귀 실행한다.

실제 시세 인증·데이터 수신 검증과 고정 데이터 테스트는 구분해 보고한다. 시세 API를 호출하지 않았다면 실시간 연동 검증 완료로 쓰지 않는다. 운영 DB 변경·서버 재시작·배포는 구현 작업에 포함하지 않는다. 실제 저장 구조와 사용 방법은 [사용 안내](strategy-paper-trading.md)를 따른다.
