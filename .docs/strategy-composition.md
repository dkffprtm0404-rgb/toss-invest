# 개별 전략과 통합 전략 사용 방법

통합 전략은 형식 4를 사용한다. 기존 형식 1·2의 개별 종목 전략과 형식 3의 상대강도 포트폴리오는 그대로 실행한다.

## 화면에서 사용하기

1. `전략 원문`에 여러 전략을 입력하고 해석한다. 6개를 입력하면 개별 초안 6개와 `전체 토탈 · 6개`가 함께 나온다. 한 전략에는 토탈을 중복 생성하지 않는다.
2. 개별 초안은 그대로 저장할 수 있다. 일부만 조합하려면 원하는 개별 초안을 2개 이상 체크하고 `선택한 전략 조합`을 누른다.
3. 토탈 또는 선택 조합에서 진입·청산의 AND/OR를 확정한다. 각 전략의 내부 필터와 괄호를 유지한다. 중첩 그룹은 3단계, 말단 조건은 진입·청산 합계 30개까지 지원한다.
4. 원문별 보완 질문의 답, 조건 변경·제외 사유를 기록한다. 미지원 원문은 개별 초안을 보완해 다시 조합하거나 사유를 적고 제외한다. 제외 후 다시 포함할 때에는 조건을 추가하거나 원본에서 재조합한다.
5. 공통 위험 관리와 청산 적용 범위, 최대 보유 수, 배분 방식을 직접 선택한다. 원문의 손절이 서로 다르면 자동으로 하나를 고르지 않는다. 위험 규칙을 모두 사용하지 않는 선택도 확인해야 한다.
6. 공통 위험·청산 확인 → `입력 조건 검증` → 최종 저장 확인 → 저장한다. 이후 조건을 편집하면 확인과 검증이 해제된다.
7. 저장된 버전을 선택해 종목·기간·체결 방식·초기자금·비용을 입력하고 실행한다. 상대강도 없는 조합은 해당 종목의 캔들만 사용한다. 상대강도가 있으면 특정 종목 하나를 거래하더라도 비교 시장 자료가 필요하다.

토탈 생성과 선택 조합에는 추가 Codex 호출이 없다. 한 번 해석된 개별 조건을 복사한다. 원래 초안을 나중에 수정해도 기존 토탈·조합·저장 버전은 바뀌지 않는다. 토탈에 보완 사항이 남아 있어도 정상 개별 전략은 저장·실행할 수 있다.

## 실행 기준

- 모든 신호와 손절은 완성 일봉 종가에서 판단한다. 체결 방식은 당일 종가 가정 또는 다음 입력 거래일 시가를 직접 선택한다.
- 한 종목의 보유분은 하나다. 여러 그룹이 동시에 참이어도 중복 매수하지 않는다. 이미 보유 중인 종목은 신규 진입 신호가 거짓으로 바뀌었다는 이유로 청산하지 않는다.
- OR에서 준비된 분기 하나가 참이면 진입할 수 있다. AND는 모두 참이어야 한다. 준비 이력 부족과 조건 미충족을 근거에서 구분한다.
- 상대강도 주간 후보는 다음 선정일까지 유지하며, 후보 안에서 일별 진입 신호를 검사한다. 순위 이탈 청산 여부를 별도로 선택한다.
- `신규 진입 때만 배분` 또는 `주간 동일 비중 재조정`을 선택한다. 주간 재조정에는 상대강도 규칙의 주간 계산일이 필요하다. 종목별 자금은 계좌 평가액/최대 보유 수이며, 미진입 몫과 정수 주수 잔액은 현금으로 남는다.
- 청산이 진입·재조정보다 우선하며 당일 전량 청산 종목은 재진입하지 않는다. 비용은 명시한 수수료·매도세·슬리피지만 반영한다.
- 고정 손절은 현재 평균 매입가격, 추적손절은 최초 진입 이후 최고 종가/고가, ATR 손절은 최초 진입가격과 그 직전 완성 봉 ATR로 계산한다. 부분 매도·추가 매수는 추적 고점과 ATR 손절 가격을 초기화하지 않는다.
- 여러 청산 사유가 겹치면 한 번만 매도하고, 함께 충족한 사유를 판정 근거에 남긴다. 종료일 강제 청산은 하지 않는다. 다음 봉이 없으면 미체결 내역을 저장한다.

## API와 저장

- `POST /api/strategy-assistant/interpret-batch`: 기존 `items`, `questions` 유지. 2개 이상이면 `total`을 추가한다.
- `POST /api/strategy-assistant/compose`: `{ "items": [기존 Item 응답 2~10개], "name": "사용자 조합" }`. 기존 Draft 구조를 반환한다. 로컬 요청과 `X-Strategy-Local: 1` 헤더가 필요하다.
- 검증 및 전략/버전 저장 API는 기존 경로를 사용한다. `schemaVersion: 4`, `composition`을 검증하며, 출처 스냅샷은 버전 1~3만 허용한다.
- 실행: `POST /api/strategies/{id}/composite-backtests`.
- 이력 목록: `GET /api/strategies/{id}/composite-backtests`.
- 단일 이력: `GET` 또는 `DELETE /api/composite/runs/{id}`.

특정 종목 조합 실행 예:

```json
{
  "version": 1,
  "symbol": "005930",
  "startDate": "2025-01-02",
  "endDate": "2025-12-30",
  "executionMode": "NEXT_DAY_OPEN",
  "initialCapital": 10000000,
  "commissionRate": 0.00015,
  "taxRate": 0,
  "slippageRate": 0
}
```

위 비용은 API 형식을 설명하는 예이며 실제 거래 비용을 의미하지 않는다. 상대강도 조합에는 [포트폴리오 자료 형식](strategy-portfolio.md)의 `universe`를 추가한다. `symbol`을 생략하면 선정된 여러 종목을 거래한다.

실행 응답의 `snapshot.result.account`는 계좌·거래·선정·보유 결과, `snapshot.result.evaluations`는 날짜/종목/조건 ID별 실제값·기준값·준비 상태·판정 사유다. 원문별 출처·수정 이유·실행 당시 전략 버전·캔들·자료 해시도 함께 저장한다. 이력 조회는 현재 전략이나 캔들로 다시 계산하지 않는다. 전략 삭제 시 해당 통합 이력도 함께 삭제되며 공유 캔들은 유지한다.

## 범위와 적용

전략별 독립 포지션·독립 손절, 장중 매매, 임의 수식, 전체 시장 과거 자료 자동 수집은 포함하지 않는다. 기존 단계식 트레일링은 버전 1~2에서 유지하며 통합 전략에서는 비율 추적손절을 사용한다. 상대강도만 남기고 진입 조건을 전부 제거한 전략은 기존 버전 3을 사용한다.

빌드 후 사용 중인 애플리케이션을 재시작하고 브라우저를 강력 새로고침해야 새 API와 정적 화면이 적용된다. 이번 작업의 검증 서버는 별도 임시 H2 서버이며 사용자 실행 서버·DB는 재시작하거나 변경하지 않는다.

검증 명령과 결과는 [구현 기록](strategy-composition-implementation.md)에 기록한다.

## 화면 검증 보완 (2026-09-21)

- 결과 상단에서 요청 기간, 실제 계산 기간, 계산 거래일 수를 구분한다. 기간이 다르면 휴장일 또는 데이터 누락 여부를 확인하도록 안내한다. 거래일 수만으로 중간 누락이나 전체 시장 캘린더의 완전성을 보장하지 않는다.
- 저장된 조건 판정에서 말단 조건의 준비 이력 부족을 종목·진입/청산·조건별로 집계한다. OR가 참이어도 평가하지 못한 분기가 있으면 제목에 `데이터 범위·이력 확인 필요`를 덧붙이고, 수익률 위에 부족한 조건과 판정일 수를 표시한다. 판정하지 않은 날짜는 분모에 포함하지 않는다.
- 표시용 정보는 기존 실행 스냅샷에서 계산한다. DB 상태 코드·매매 규칙·저장 데이터는 변경하지 않는다. `완료`는 계산 완료이며 모든 조건의 이력이 충분하다는 뜻은 아니다.
- 검증 결과를 편집기 아래 검증 버튼 가까이에 배치하고, 검증 후 결과 영역으로 스크롤과 키보드 초점을 이동한다. 검증 실패 시 저장 차단은 유지한다.
- 조건 하나인 그룹에는 결합 방식 선택이 필요 없다고 안내한다. 두 번째 조건을 추가하면 AND/OR 선택이 다시 나타나며, 저장된 연산자는 보존한다.
- 원문 미리보기는 따옴표나 이스케이프된 줄바꿈 없이 원래 문자열을 표시한다. 구조화된 스냅샷은 JSON으로 표시하며, 모든 내용은 HTML로 실행하지 않는 텍스트로 출력한다.
