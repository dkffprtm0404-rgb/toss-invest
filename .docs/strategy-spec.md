# 사용자 전략 명세

작성일: 2026-09-08  
기준: [프로젝트 기획서](project-plan.md), [기존 엔진 검증](engine-validation.md)

이 문서는 자연어로 만든 전략을 백테스트와 모의매매가 같은 의미로 해석하도록 정의한다. 2026-09-08의 명세 초안을 바탕으로 2026-09-09 사용자가 3단계 설계와 세부 구현 진행을 승인했다. 현재 Java 명세·검증기·공통 판정기와 사용자 전략 백테스트 API를 구현했다. 실제 필드·실행 예제·오류·계산 기준은 [사용자 전략 백테스트 API](user-strategy-backtest.md)를 따른다. 전략 저장과 LLM·웹·전략별 모의매매 실행 연결은 후속 단계다.

## 사용자 확인이 완료된 사항

### 체결 방식 선택

사용자가 실행할 때 아래 두 방식 중 하나를 선택한다.

- `SAME_DAY_CLOSE`: 해당 일봉의 종가로 조건을 판단하고 같은 종가로 체결한다.
- `NEXT_DAY_OPEN`: 해당 일봉의 종가로 조건을 판단하고 다음 거래일 시가에 체결한다.

두 방식 모두 매수와 매도, 손절과 익절에 동일하게 적용한다. 장중 고가·저가가 기준에 도달했다는 이유만으로 별도 체결하지 않는다. 다음 거래일 시가 방식에서는 신호 시점 가격과 실제 체결 가격이 달라질 수 있다. 따라서 손절률 5%는 손실을 반드시 5%로 제한한다는 뜻이 아니다.

예를 들어 매수가 100이고 손절 조건이 -5%일 때, 종가 94에서 손절 조건이 발생하고 다음 시가가 92라면 다음 시가 방식의 체결 가격은 92다. 종가 방식의 체결 가격은 94다. 실제 비용 반영 방식은 별도 결정한다.

실행 결과에 선택한 방식을 포함한다. 신호 시점과 체결 시점도 구분해 기록한다. DB 저장과 비교 화면의 차이 표시는 후속 단계다.

### 시간 청산

기존 조건을 유지한다. 설정한 거래일 수를 **초과**했고 트레일링이 활성화되지 않았을 때 시간 청산 조건을 발생시킨다. 5거래일 설정에서 5일에 도달한 즉시 강제 청산하는 방식은 아니다.

트레일링이 활성화됐다면 시간 청산으로 덮어쓰지 않는다. 시간 청산 조건 발생 후 실제 체결 시점에는 사용자가 선택한 체결 방식을 적용한다.

필드는 `risk.timeExit.days`, 의미는 '시간 청산 기준 거래일 수'다. 매수 봉을 0으로 두고 이후 저장 일봉 수를 센다. 존재하지 않는 휴장·거래 정지일을 추가하지 않는다. 거래량 0인 유효 가격 봉은 일수에 포함하지만 그 봉에서 체결할 수는 없다.

### 트레일링의 3% 기준

사용자는 트레일링을 3% 기준으로 계산하도록 지시했다. 시작 3%에서 보호선 0%, 최고수익률 6%에서 보호선 3%, 최고수익률 9%에서 보호선 6%가 되는 기존 코드의 간격을 기준으로 정리한다.

사용자 확인에 따라 보유기간 3거래일 초과 시 시작 기준을 1.5%로 낮추는 기존 규칙도 유지한다. 완화 후에는 최고수익률 1.5%에서 보호선 0%, 4.5%에서 보호선 3%, 7.5%에서 보호선 6%가 된다. 상승 간격은 계속 3%p다.

활성 여부도 기존 코드처럼 보유기간 전체의 최고수익률을 현재 적용하는 시작 기준과 비교한다. 최고수익률은 종가로 갱신한다. 따라서 기준이 1.5%로 낮아지면 이전에 기록한 최고수익률도 그 기준으로 평가한다.

### 필수값 보완 입력

사용자가 선택한 각 정책에 필요한 값이 빠져 있으면 반드시 사용자에게 보완 입력을 받는다. LLM과 서버는 누락값을 임의의 기본값으로 채우지 않는다. 필요한 값이 모두 채워지고 검증을 통과하기 전에는 전략을 실행하지 않는다.

예를 들어 '골든크로스면 매수'는 상향 교차라는 방향은 입력했지만 이동평균 종류와 단기·장기 기간은 입력하지 않은 상태다. 이 경우 이미 지정한 방향을 다시 묻지 않고 누락된 세 값만 질문한다. 사용자가 보완한 값도 기간 관계 등 검증을 다시 통과해야 한다.

질문에는 해당 조건의 위치, 필요한 값, 질문 문구를 포함한다. 여러 값이 없으면 누락 목록을 함께 반환하고, 답변으로 해결된 항목은 다음 질문 목록에서 제외한다. 입력하지 않음과 수치 0을 구분하여, 잘못된 값에는 수정이 필요한 이유를 안내한다.

전략 조건과 실행 조건은 각각 검사한다. 조건을 모두 작성해도 종목·기간·체결 방식이 없으면 실행 입력을 추가로 받는다. 입력 검증 통과는 엔진 연동과 데이터 검증까지 완료됐다는 뜻은 아니다.

선택한 정책별 필수 데이터는 다음과 같이 정리한다.

- 이동평균 교차: 이동평균 종류, 단기 기간, 장기 기간, 교차 방향.
- RSI: 계산 방식, 기간, 기준값, 비교 방식.
- 거래량: 평균 계산 기간, 비교 배수, 비교 방식.
- 복수 조건: AND·OR 결합 방식. 조건 하나에는 결합 방식이 필요하지 않다.
- 손절: 손절률. 입력된 비율의 단위와 부호를 명확히 표시한다.
- 고정 익절: 익절률.
- 시간 청산: 기준 거래일 수.
- 트레일링: 이 문서에서 확인한 기존 정책을 선택했음을 확인하고 3%·1.5% 완화와 3%p 간격을 표시한다. 이를 사용자에게 숨겨진 자동 선택으로 적용하지 않는다.
- 백테스트 실행: 종목, 시작일, 종료일, 체결 방식. 자금·비용 모델이 확정되어 추가되면 해당 모델에 필요한 값도 같은 정책으로 검사한다.

### 청산 조건은 선택 사항

사용자 확인에 따라 매수 조건만 있고 청산 방법을 지정하지 않은 전략도 실행을 허용한다. 손절·익절·트레일링·시간 청산·지표 매도를 추가하도록 강제하지 않으며 기존 전략의 청산 규칙을 자동으로 붙이지 않는다.

'손절을 선택하지 않음'과 '손절을 선택했지만 손절률을 입력하지 않음'을 구분한다. 전자는 허용하고, 후자는 손절률을 반드시 보완받는다. 다른 선택 정책에도 같은 기준을 적용한다.

데이터 종료까지 남은 포지션은 미청산 평가손익으로 표시한다. 결과 산출을 위한 강제 매도는 하지 않으며 완료 거래 지표와 분리한다.

## 전략과 실행 설정의 구분

전략에는 무엇을 보고 매수·매도하는지 저장한다. 실행 설정에는 어떤 종목·기간·체결 방식으로 검증했는지 저장한다. 같은 전략을 두 체결 방식으로 비교할 수 있도록 둘을 구분하는 설계다.

### 전략 데이터와 후속 저장 범위

- `schemaVersion`: 전략 표현 형식의 버전.
- `name`: 사용자가 정한 전략 이름.
- `originalPrompt`: 입력한 원문.
- `entry`: 매수 조건과 조건 결합 방식.
- `exit`: 지표에 따른 매도 조건.
- `risk`: 손절률, 고정 익절, 트레일링과 시간 청산 조건.
- 사용자 보완 입력 기록: 어떤 누락값을 질문했고 사용자가 어떻게 답했는지 보존하는 기능은 저장·LLM 단계에서 구현한다. 현재 검증기는 누락 위치와 메시지를 반환하고 자동 기본값을 적용하지 않는다.

전략의 저장 버전과 명세 형식 버전은 구분한다. 수정 전 전략으로 실행한 결과는 당시 전략 내용을 보존한다.

### 실행 데이터 제안

- 전략 버전과 실행 당시 명세.
- 종목, 기간과 봉 주기.
- `executionMode`: `SAME_DAY_CLOSE` 또는 `NEXT_DAY_OPEN`.
- 시세 데이터 기준과 사용한 가격 종류.
- 초기 자금·거래 비용 등 확정된 실행 가정.
- 실행 상태와 오류 정보.

현재 `StrategyDefinition`, `UserStrategyBacktestRequest`와 `POST /api/backtest/run-strategy`로 구현했다. 전략 형식 버전 `schemaVersion`과 이름·원문을 받을 수 있지만 저장 버전·보완 이력·자금·비용 모델은 아직 구현하지 않았다. 응답은 실행 당시 입력 스냅샷을 포함한다.

## 첫 버전의 조건 범위

이동평균 교차, RSI, 거래량 조건과 손절·익절·시간 청산·트레일링을 지원한다. 조건은 한 단계 AND 또는 OR로 묶고 중첩 논리식은 지원하지 않는다.

- 이동평균 교차: SMA 또는 EMA, 단기·장기 기간, 상향·하향 교차.
- RSI: 기간, 기준값, 이상·이하 또는 기준값 상향·하향 돌파.
- 거래량: 직전 N개 봉 평균 대비 배수 조건.
- 가격 기반 청산: 손절, 고정 익절, 트레일링.
- 시간 청산: 기준 거래일 초과와 트레일링 활성 상태를 함께 평가.

RSI는 기존 단순 평균 방식 `SIMPLE`만 지원하며 평탄 구간 100 동작을 명시한다. 기간은 정수 1~500봉, 그룹은 1~20조건이다. 필요한 값이 없으면 사용자에게 보완받으며 자동 기본값은 적용하지 않는다. 기존 점수제의 거래대금·급등 필터·거래 중단 규칙은 새 사용자 전략에 적용하지 않는다. 기본 전략은 기존 API에서 실행한다.

## 처리 흐름

1. 사용자가 자연어를 입력한다.
2. LLM이 지원하는 전략 형식으로 해석한다.
3. 서버가 필수값, 지원 조건, 수치와 조합을 검증한다.
4. 해석된 조건과 미해결 항목을 화면에 표시한다.
5. 사용자가 조건을 확인하고 전략을 저장한다.
6. 종목·기간과 체결 방식을 선택해 실행한다.
7. 엔진이 거래·지표·신호 및 체결 시점을 반환한다.

LLM은 조건을 해석하고 결과를 설명한다. 실제 매매 판단과 지표 계산은 검증된 명세를 사용하는 엔진이 수행한다.

## 3단계에서 확정·구현한 정책

### 청산 후 재진입

기존 엔진의 동작은 유지한다. 새 사용자 전략은 같은 종가에서 청산 후 재진입하지 않는다. 다음 시가 방식의 시가 청산 후 그날 종가에 나온 새 신호는 다음 시가 주문으로 허용한다.

### 거래일과 유효 가격

새 실행은 매수 봉을 0으로 한 저장 일봉 수를 사용한다. OHLC가 양수가 아니거나 서로 모순되면 데이터 오류로 반환한다. 체결 봉의 거래량이 0이면 실행 오류로 반환하며 가격을 보정하거나 주문을 임의 이월하지 않는다. 날짜 공백은 추정하지 않으며 다음 시가는 다음 저장 일봉의 시가다. 기존 모의매매의 달력 일수 계산은 전략별 모의매매 연결 단계에서 이 계약에 맞춰 연결해야 한다.

### 데이터 끝의 포지션과 대기 주문

기존 엔진의 강제 종료는 유지한다. 새 사용자 전략은 마지막 종가로 보유분을 평가해 `openPosition`에 반환한다. 다음 시가가 없는 마지막 신호는 `pendingOrder`의 `NO_NEXT_BAR` 상태로 반환한다. 둘 모두 완료 거래 성과에서 제외한다.

### 비용과 성과 지표

기존 거래 단위 평균·합산 수익률·승률·낙폭·샤프를 의미가 명확한 필드로 제공한다. 계좌 수익률·일별 평가자산 곡선은 제공하지 않는다. 자금 배분·수량·수수료·세금·슬리피지를 임의 설정하지 않는다. 가격 리스크는 정확한 가격끼리 비교하고 보고용 거래 수익률만 소수 6자리로 반올림한다.

### 거래 중단 규칙

기존 최근 20건 승률 규칙과 최근 손실에 의한 거래 중단은 새 사용자 전략에 적용하지 않는다. 기존 기본 전략에는 종전대로 남아 있다.

## 구현 구조

기존 패키지 구조를 따라 `strategy`에 전략 명세·검증·공통 판정기를 뒀다. `backtest`에는 검증한 명세와 실행 설정을 받는 `UserStrategyBacktestEngine`·서비스·컨트롤러를 추가했다. 기존 점수제 엔진의 운영 로직은 변경하지 않았다. 모의매매는 후속 단계에서 같은 `StrategyEvaluator`를 재사용한다.

체결 방식은 이름이 명확한 enum과 일반적인 분기로 시작한다. 확장 필요가 확인되기 전에는 플러그인 구조, 범용 규칙 언어, 과도한 인터페이스 계층을 도입하지 않는다. 메서드 이름은 동작을 설명하고 주석은 코드만으로 알기 어려운 정책과 이유를 기록한다.

### 체결 시점에 따른 처리 순서

당일 종가 방식은 완성된 봉으로 지표·신호를 계산하고 해당 봉 종가를 체결 가격으로 사용한다. 이 방식은 종가를 확인한 뒤 같은 가격에 체결됐다고 가정하는 시뮬레이션임을 화면과 결과에 표시한다.

다음 거래일 시가 방식은 이전 거래일에 확정한 주문을 시가에서 처리한 뒤, 그날 종가가 확정되면 다음 거래일 주문을 판단하는 순서로 구성한다. 당일 종가 정보를 그날 시가 체결 결정에 사용하지 않는다.

손절 신호와 실제 체결을 구분하므로 거래의 `entry`/`exit`에는 `signalTimestamp`, `executionTimestamp`, `price`, `reason`, `evidence`를 반환한다. 원본 봉 타임스탬프도 포함한다. 시각은 한국 시간 09:00/15:30의 시뮬레이션 가정이다. 체결 가격이 없는 마지막 신호는 미체결로, 유효하지 않은 시세는 오류로 구분한다.

## 구현 검증 시나리오

- 동일 전략과 시세에서 종가 방식과 다음 시가 방식의 체결 가격·시점이 정확히 구분된다.
- 장중 손절선 하회 후 종가 회복 시, 두 방식 모두 그 장중 가격만으로 손절하지 않는다.
- 종가에서 발생한 손절 신호는 선택 방식의 체결 시점으로 이어진다.
- 시간 기준과 트레일링 활성 조건을 함께 평가한다.
- 체결 가격이 없는 주문을 가상의 가격으로 채우지 않는다.
- 모호하거나 지원하지 않는 전략은 보완이 완료되기 전 실행하지 않는다.
- 같은 명세·실행 설정·데이터에서 결과를 재현할 수 있다.
