## 공통 제약과 가정

- 대표가 질문 없이 계속 진행을 지시했다. 기존 저장소에서 되돌릴 수 있는 구현·격리 검증을 기본값으로 한다.
- 새 의존성·공개 HTTP API·매매 계산 정책을 추가하지 않는다. 실제 운영 DB·저장 전략·실행 스냅샷은 조작하지 않는다.
- 기존 공유 체크아웃의 미커밋 변경을 보존한다. 현재 Git 상태 조회가 승인 거절돼 임의 체크아웃·worktree 이동·커밋을 하지 않는다.
- 도구의 명시적 거절을 다른 실행 경로로 우회하지 않는다. 허용된 파일 읽기·편집·사무실 보고로 가능한 작업을 계속한다.
- 실행이 차단되면 RED/GREEN·컴파일·테스트·운영 복구를 성공으로 기록하지 않는다. 수행하지 못한 명령과 원인을 최종 보고에 남긴다.
- 기존 보류 QA 카드는 새로 만들지 않는다. 전체 카드 조회는 불가하므로 확인한 문서와 이번 도구 결과만 연결한다.
- 삭제·배포·push·외부 쓰기·실운영 스키마 반영은 수행하지 않는다. 격리 테스트의 합성 자료·모의 외부응답을 실제 시장 확인과 구분한다.

## 독립 검토 중점

1. 단일 전략 A 뒤 미지원 B 선택 시 내부 대상·표시·시작 요청이 모두 해제되는가.
2. 늦은 준비 상태 응답, 확인란, 입력 변경이 실행 허용을 잘못 복원하지 않는가.
3. 포트폴리오 예시가 실제 구성/거래일 확보로 오인되지 않고 오류 필드와 수정 위치를 보여 주는가.
4. 국내 시세 복구에서 저장 당시 미국 지수·뉴스·근거 ID를 유지하고 새 요약을 재검증하는가.
5. 직렬화·DB 저장·동시 교체 실패 시 본문과 원본 이력이 함께 보존되는가.
