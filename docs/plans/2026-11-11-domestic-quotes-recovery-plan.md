## 1. 현재 확인한 사실과 미확인 사항

- 현재 작업 공간의 `MarketBriefingSources.java`에는 네이버 지수 차트·일별 환율 우선 수집과 Yahoo 보조 수집이 이미 있다. 대표가 인계한 “Yahoo 단독” 상태와 차이가 있다.
- `MarketBriefingService.java`에는 `hasStaleLocalQuote`, `upgradesQuotes`, `withReferenceWarnings`와 오늘 재시도 경로가 있다.
- `MarketBriefingEntity.java`에는 `snapshotHistoryJson`과 `@Version`이 있고, 서비스에는 교체 전 이전 JSON을 추가하는 코드가 있다.
- 기존 수집·서비스 테스트에 11-10 자료 선택, 환율, fallback, stale 재시도, 이전 JSON 보존 사례가 있다. 테스트 소스의 존재를 확인했으며 실행 결과는 확인하지 않았다.
- `MarketBriefingController`와 `MarketBriefing`의 공개 응답 구조, 화면의 날짜·경고 표시 코드를 읽었다.
- 기존 구현의 작성 주체·Git 변경 상태·운영 반영 여부는 미확인이다. Git은 저장소 소유권 오류가 났고, 명령 단위 예외를 지정한 읽기 조회도 `rejected by user`로 거절됐다. 상세 거절 사유는 제공되지 않았다. 전역 Git 설정은 변경하지 않는다.
- 실제 DB, 2026-11-11 저장 JSON, 외부 시세 응답, 모델 호출, 컴파일·테스트·서버 실행은 확인하지 않았다.
- 따라서 기존 관련 구현을 보존하고 요구사항 충족 여부를 확인한 뒤 필요한 부분만 보완한다. 이미 작성된 코드를 새 작업 성과로 합산하지 않는다.

## 2. 요구사항과 설계 결정

### R1. 국내 시세 공급자 우선순위

- `KOSPI`·`KOSDAQ`는 현재 코드의 네이버 공개 지수 일별 차트 경로를 우선 사용한다.
- `USDKRW`는 현재 코드의 네이버 일별 환율 경로를 우선 사용한다.
- 현재 소스에 적힌 경로는 다음과 같다. 이번 기획에서 실제 응답·가용성을 확인한 주소는 아니다.
  - `https://api.stock.naver.com/chart/domestic/index/KOSPI?periodType=dayCandle`
  - `https://api.stock.naver.com/chart/domestic/index/KOSDAQ?periodType=dayCandle`
  - `https://api.stock.naver.com/marketindex/exchange/FX_USDKRW/prices?page=1&pageSize=60`
- 네이버 실패·형식 오류·유효 자료 부족 시 기존 Yahoo 경로를 보조로 사용하고 공급자 전환 경고를 남긴다. 양쪽 실패 시 시세를 만들지 않는다.

### R2. 기준일과 숫자의 의미

- 생성 대상일과 원본 시세 기준일을 구분한다. 고정 회귀 입력은 2026-11-11 08:30 KST, 직전 KRX 거래일을 11-10으로 설정한다. 테스트 가격은 합성 자료임을 명시한다.
- 기준 시각 이전에 완료된 유효 일별 자료만 선택한다. 당일 장중·미래 자료, null·0·음수·파싱 불가 가격을 정상 시세로 만들지 않는다.
- 순서가 뒤섞인 응답에서도 날짜로 최신 두 유효 일별 값을 선택한다. 등락률은 같은 공급자의 두 값을 사용하며 비율 단위 `0.1 = 10%`를 유지한다.
- 최신 Yahoo 봉이 null이어도 이전 봉의 날짜를 직전 거래일로 바꾸거나 메타데이터 가격으로 추측하지 않는다. 보조 자료가 오래됐으면 실제 날짜와 경고를 유지한다.
- 네이버 환율의 날짜 필드에는 실제 체결 시각이 없다는 전제를 유지한다. 코드의 날짜 종료 경계는 완료 판정용이며 실제 은행 마감·고시 시각으로 설명하지 않는다.
- 기존 Yahoo 환율의 봉 종료 시각과 원자료 기준일이 하루 어긋나는 경우를 별도 검토한다. 관측시각을 단순 KST 날짜로 바꿔 오래된 가격을 최신으로 판정하지 않는다. 원본 저장 JSON은 수정하지 않는다.

### R3. 오늘 stale 저장본만 재시도

- KST 오늘 날짜의 `READY/PARTIAL` 저장본에서 대상 국내 시세가 직전 거래일보다 오래됐거나 기준일 확인이 불가능한 경우에만 이 복구 경로를 연다.
- 정상 최신 저장본, 뉴스 누락만 있는 `PARTIAL`, 과거 날짜의 저장본은 이 변경만으로 재생성하지 않는다.
- 복구 입력은 기존 스냅샷에 개선된 대상 국내 시세를 병합한다. 저장 당시 미국 지수·뉴스 근거는 유지하며, 근거 ID와 숫자가 달라진 요약은 기존 검증을 거쳐 다시 생성한다. 가격만 바꾸고 옛 요약을 남기지 않는다.
- `SP500/NASDAQ`의 Yahoo 수집과 연합뉴스·CNBC RSS의 기존 정책은 유지한다.
- 대상 국내 시세의 실제 기준일이 하나 이상 개선되고, 다른 기존 시세가 누락되거나 더 오래되지 않은 경우만 교체 후보로 삼는다.
- 개선이 없으면 AI 호출·저장·이력 추가를 하지 않는다. 일부만 개선되면 남은 오래된 자료의 경고와 `PARTIAL`을 유지한다.
- 예약 시각·휴장 처리·KST 날짜당 자동 3회 제한과 수동 오늘 재시도 경로를 유지한다. 반복·무제한 자동 복구를 추가하지 않는다.

### R4. 저장 안전성과 원본 보존

- 수집 실패, 기준일 개선 없음, 기존 시세 누락·퇴행, AI 실패, 숫자·출처 검증 실패 시 기존 공개 저장본을 유지한다.
- 교체가 확정될 때 기존 `snapshotJson` 문자열을 재직렬화하지 않고 그대로 `snapshotHistoryJson`에 보존한다. 기존 보존 이력도 유지한다.
- 이전 JSON 보존과 새 스냅샷 교체는 같은 DB 쓰기 단위에서 성공해야 한다. 직렬화·저장 실패 또는 동시 변경 시 부분 교체나 이전 이력 유실이 없어야 한다.
- 기존 `@Version`과 nullable 이력 필드의 호환성을 확인한다. 추가 테이블·정리 작업·DB 삭제나 실제 스키마 반영은 하지 않는다.
- 신규 `FAILED/NO_DATA` 결과가 기존 `READY/PARTIAL`을 덮어쓰지 않아야 한다.

### R5. 경고와 공개 계약

- 국내 두 지수와 원달러 모두 실제 기준일·기대 직전 거래일·자료 부족을 한국어로 안내한다. 원달러만 경고에서 빠지지 않아야 한다.
- 기준일을 알 수 없거나 거래일 계산이 실패하면 최신이라고 단정하지 않고 안전하게 기존 저장본을 유지한다.
- `GET /api/market-briefings/latest`, 목록, 날짜별 조회, `POST /api/market-briefings/today`의 경로·응답 필드·상태값·로컬 요청 보호를 유지한다.
- `MarketBriefing.Source`의 ID·필드·단위와 `changeRate`의 비율 의미를 유지한다. 내부 이력 JSON·버전은 공개 응답에 추가하지 않는다.
- GET 조회로 시세 재수집·AI 재생성·저장본 교체를 하지 않는다. 기존 화면의 시세 기준일·경고·출처 표시와 새 수집 결과가 호환돼야 한다.

## 4. 담당과 파일 소유권

아래 6개 책임 중 팀원 5명의 업무를 앱의 하위 카드로 제안한다. 서버 개발 담당은 팀장 본인이므로 하위 카드로 자기 배정하지 않고 상위 카드에서 직접 담당한다. 기존 코드가 있는 만큼 각 담당자는 먼저 현재 파일을 읽고 중복 구현을 피한다. 공통 기획서의 소유자는 리드다.

### 1) 자료 조사 담당 — 공개 시세 계약·기준일 검토

- 대상: `MarketBriefingSources.java`, 기존 수집 테스트, 기존 문서의 자료 설명. 제품 파일은 수정하지 않는다.

- [ ] 실제 응답으로 확인하지 못한 항목은 미확인으로 표시하고 회귀 fixture의 계약·합성 자료 구분을 제시한다.
- [ ] 날짜 경계·null·자료 부족·기존 Yahoo 환율 해석의 위험을 근거 위치와 함께 보고한다.
- 산출물: 리드에게 출처 계약·미확인 사항·fixture 검토 결과. 외부 요청은 하지 않는다.

## 5. 진행·취합 방식

1. 승인 후 앱이 조사·품질·화면 호환성·문서·코드 검토 5건을 팀원에게 배정한다. 서버 보완은 상위 업무 카드 책임자인 리드가 직접 수행한다. 초기 소스·테스트·공개 계약은 이 기획에 적은 현재 파일을 공통 출발점으로 삼는다.
2. 담당자는 소유 파일만 수정한다. 조사·호환성·독립 검토는 읽기 전용으로 진행하며, 발견한 필수 수정은 리드에게 반환한다.
3. 각 보고에는 변경 파일, 확인한 근거, 정적 검토 결과, 미실행 검증, 가정, 대표 확인 필요 명령을 포함한다.
4. 전원 결과를 받은 후 리드가 최종 파일을 다시 읽어 요구사항을 대조하고 서버 소스를 직접 보완한다. 병렬 작업 중 검토 뒤에 바뀐 부분과 리드의 후속 변경은 최신 파일을 기준으로 다시 정적으로 확인한다.
5. 소스·문서에서 해결 가능한 필수 누락은 보완하고 최종 보고한다. 실행 검증·서버 반영은 승인 대상 단계로 남긴다.
6. 이 기획을 대신 수행하는 별도 “할 일” 카드 실물은 확인하지 못했다. `absorbs`는 빈 목록으로 제출한다. 문서 안의 제안·회의 할 일 제목을 실제 카드로 간주하지 않는다.

## 6. 가정

- 현재 업무의 프로젝트는 관련 구현·문서가 확인된 위 Toss Invest 저장소다.
- 사용자가 지정한 2026-11-11 사례의 회귀 테스트에서 11-10을 거래일로 고정한다. 실제 거래일 계산은 기존 KRX 달력을 재사용한다.
- 원달러 최신성의 최소 요구 기준도 기존 국내장 준비 목적에 맞춰 직전 KRX 거래일로 둔다. 실제 공급자의 자료 기준일을 다른 날짜로 바꾸지 않는다.
- “미국 지수/뉴스 유지”는 기존 수집 정책을 유지하고, 오늘 저장본 복구 중에는 저장 당시 비대상 근거를 보존하는 의미로 적용한다.
- 실행 금지는 Gradle·Node·PowerShell/Python 프로젝트 스크립트·서버 시작·실연동 요청에 적용한다. 이번 단계는 파일 읽기·정적 소스/문서 편집·요청된 사무실 내부 보고만 수행한다.
- 기획서는 `docs/plans/`에 저장한다(2026-11-17 문서 통합 경로 반영).
