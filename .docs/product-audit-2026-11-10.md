## 1. 종합 판단

전략 작성 → 검증 → 버전 저장 → 백테스트 → 결과 분석·비교 → 단일 종목 모의매매의 기능 연결은 갖춰져 있다. 실행 당시 전략과 가격 자료를 보존하는 구조, 저장 전 확인, 성과 계산 기준 설명, 브리핑 출처·관측 시각 표시는 장점이다.

사용자 편의성에 대한 팀장 판단은 **투자·개발 용어에 익숙한 로컬 사용자에게는 활용 가능하지만, 처음 사용하는 일반 사용자에게는 준비 절차와 실패 복구 안내가 더 필요하다**는 것이다. 기능 추가보다 종목별 표시 정확성과 실패 상태의 전달을 먼저 보완하는 편이 타당하다.

회원별 권한이 필요한 외부 서비스로 사용하려면 인증·소유권 검사를 별도로 갖춰야 한다. 현재 코드의 개발용 접근 허용 설정을 확인했으며, 실제 외부 노출이나 침해가 발생했다고 판단한 것은 아니다.

## 3. 우선 확인·수정할 오류

심각도는 P1=표시·실행 결과를 잘못 해석할 수 있어 먼저 대응할 항목, P2=일부 경로의 오류 또는 복구·운영 불편이다. 보안 항목은 외부 제공 전 별도 조건부 관문으로 다룬다.

### E1. P1 — 종목을 바꾼 뒤 이전 종목 응답이 현재 화면에 표시될 수 있음

- **발생 조건:** A 종목 조회가 끝나기 전에 B 종목을 선택하고, B 응답보다 A 응답이 늦게 도착한다.
- **코드 경로:** 선택 시 `activeSymbol`과 제목을 B로 바꾸지만, 개별 조회 함수는 응답 후 현재 종목·요청 세대를 검사하지 않고 공용 DOM에 쓴다.
- **영향:** 제목은 B인데 가격·호가·차트·매매 신호 일부가 A일 수 있다. B 조회 중 기존 내용도 즉시 비우지 않아 혼동 구간이 생긴다.
- **근거:** `src/main/resources/static/js/dashboard.js:181`, `:210`, `:221`, `:230`, `:289`, `:427`.
- **확인 수준:** 응답 순서에 따른 정적 코드 결함. 이번 점검에서 지연 응답으로 동적 재현하지 않았다.
- **개선 방향:** 선택마다 요청 세대를 부여하고, 응답 반영 전에 종목·세대를 검사한다. 이전 요청 취소와 패널별 로딩 표시를 함께 적용한다.
- **검증 기준:** A 응답을 의도적으로 지연한 뒤 B를 선택해도 모든 패널이 B 정보만 유지해야 한다. 패널 닫기·재열기에도 적용한다.

### E2. P1 — 기존 페이퍼가 종목별 실패를 정상적인 '거래 없음'처럼 반환할 수 있음

- **발생 조건:** 기존 점수 기반 페이퍼 실행 중 시세·신호 조회가 종목별로 실패한다.
- **코드 경로:** `runDaily()`는 각 Future 처리 예외를 로그만 남기고 계속한다. 반환값에는 매수·매도·보유 목록과 전체 대상 수만 있고 실패 수·원인이 없다. 컨트롤러는 그 결과를 반환하며 화면은 '완료 / 매수 없음 / 매도 없음'을 표시한다.
- **영향:** 조건이 맞지 않아 거래가 없는 경우와 평가 자체를 못 한 경우를 구분하기 어렵다. HTTP 오류를 표시하는 기존 화면 개선만으로는 이 경로가 해결되지 않는다.
- **근거:** `src/main/java/com/tossinvest/tossinvestbackend/paper/PaperTradingService.java:158`, `:203`, `:217`, `:298`; `paper/PaperTradingScheduler.java:75`; `src/main/resources/static/js/dashboard.js:565`.
- **확인 수준:** 서버 반환 계약과 화면 처리의 정적 확인. 현재 제공업체 장애 발생 여부는 확인하지 않았다.
- **개선 방향:** 성공·부분 실패·전체 실패를 결과에 포함하고, 평가 성공 수·실패 종목·안전한 사유를 화면과 실행 로그에 전달한다. 정상적인 무거래와 분리한다.
- **검증 기준:** 전체 종목 실패, 일부만 실패, 정상 무거래의 세 결과를 사용자가 구별할 수 있어야 한다.

### E3. P2 — 데이터가 없는 기존 백테스트 비교 API에서 평균이 유효한 수가 아님

- **개선 방향:** 성공·실패 종목 수와 마지막 확정봉 기준일을 제공한다. 일부 실패에서도 나머지 수집을 계속하는 기존 동작은 보존한다.

### E5. P2 — 조회 실패 뒤 오래된 자료와 갱신 시각이 함께 남을 수 있음

- **개선 방향:** 패널별 마지막 성공 시각·실패 배지와 재시도를 제공한다. 전체 갱신 결과는 성공·부분 실패를 집계한다. 남겨 둔 값에는 과거 자료임을 표시한다.

## 4. 외부 제공 전 확인할 보안 경계

### S1. 개발용 API 접근 허용과 사용자별 권한 부재

`SecurityConfig`는 `/api/**`, `/h2-console/**`, 그 밖의 요청을 모두 허용하고 CSRF·프레임 보호를 끈다. 공통 설정에는 H2 콘솔이 켜져 있고 `server.address`는 지정돼 있지 않다. 전략별 모의매매 컨트롤러의 조회·갱신·중지·삭제는 ID로 처리하며 공통 로그인·소유권 검사가 보이지 않는다.

- 근거: `src/main/java/com/tossinvest/tossinvestbackend/config/SecurityConfig.java:18`; `src/main/resources/application.yaml:15`, `:20`; `src/main/java/com/tossinvest/tossinvestbackend/strategypaper/StrategyPaperController.java:12`.
- README는 이를 개발용 설정으로 명시하고 `127.0.0.1` 바인딩 실행을 안내한다(`README.md:166`). 따라서 현재 로컬 사용 전제를 누락한 채 보안 사고라고 단정하지 않는다.
- 자연어 지원·브리핑 생성에 있는 로컬/동일 출처 검사가 모든 일반 API를 보호하는 것은 아니다.
- 외부·다중 사용자 제공을 선택하면 인증·소유권·변경 요청 보호·운영 프로필·H2 콘솔 제한을 먼저 설계하고 검증해야 한다. 이번에 적용하거나 공개 접근을 시험하지 않았다.

## 5. 부족한 기능과 사용자 편의성 개선 후보

### U1. 처음 사용자에게 데이터 준비와 다음 행동을 연결할 필요

화면에 전략 1~5단계, 조건 편집과 실행 안내가 있지만 실제 일봉 준비는 README의 Python·CSV·API 절차에 의존한다. 'Codex 연결', '사용 가능한 종목·자료 기간', '전략 유형별 실행 가능 범위'를 한 곳에서 확인하고 데이터 부족 시 다음 행동으로 연결하는 안내가 있으면 좋다. 자동 수집 버튼을 무조건 추가하거나 외부 호출을 기본 실행하자는 제안은 아니다.

### U2. 숨긴 계좌 탭에서도 계좌·시세 조회가 계속됨
