# 통합 전략 기획안

작성일: 2026-09-15. 2026-09-16 사용자 구현 승인 및 구현·검증 완료. 아래는 승인된 기획 배경이며 실제 구현 범위와 검증은 [구현 기록](strategy-composition-implementation.md), 사용 흐름은 [사용 방법](strategy-composition.md)을 참고한다.

## 목표와 현재 구조

사용자가 `전략 원문`을 한 번 입력하면 **개별 전략 초안과 전체를 담은 토탈 초안을 함께 제공**한다. 사용자는 개별 전략 하나를 쓰거나, 원하는 전략 2개 이상을 선택해 특정 종목에 적용하거나, 전체 토탈을 선택할 수 있다. 개별/통합 중 하나의 출력 모드를 먼저 고르는 방식은 사용하지 않는다.

전략이 6개이면 기본 결과는 `개별 초안 6개 + 전체 토탈 초안 1개`다. 선택한 일부 전략의 사용자 조합은 필요할 때 추가한다. 원문에서 독립 전략이 하나만 추출되면 같은 내용의 토탈을 중복 생성하지 않는 것을 제안한다.

조합을 실행할 때에는 사용자가 확정한 규칙에 따라 **하나의 전략·하나의 계좌·하나의 백테스트 결과**를 만든다. 여러 독립 전략의 수익률을 단순 합산하지 않는다. 이 문서의 이전 제안 중 입력 처리 모드 선택과 상대강도 종목 선정의 필수화는 이 목표로 대체한다.

현재는 형식 1·2의 개별 종목 조건과 형식 3의 상대강도 포트폴리오가 분리되어 있다. `ConditionGroup`은 평면 AND/OR이고, `StrategyValidator`는 portfolio와 entry/exit 혼용을 거절한다. 따라서 화면에서 초안 목록만 합치는 작업으로 해결되지 않는다.

참조: `strategy/StrategyDefinition.java`, `strategy/StrategyValidator.java`, `strategy/StrategyEvaluator.java`, `portfolio/PortfolioEngine.java`, `static/js/strategy-workbench.js`, [포트폴리오 계약](strategy-portfolio.md).

## 결합 방식의 선택

1. **전부 AND/OR로 결합:** 단순하지만 각 전략에 속한 필터와 청산 조건의 적용 범위가 바뀔 수 있다. 전체 AND는 서로 다른 교차 이벤트가 같은 날 발생해야 한다. 프로그램은 이를 표현할 수 있어야 하지만 기본 결합으로 강제하지 않는다.
2. **역할을 나눈 조건 조합 — 제안:** 특정 종목 지정 또는 필요한 종목 선정 → 신규 진입 조건 → 공통 청산·위험 관리 → 자금 배분 순서로 구성한다. 기존 조건의 소속과 괄호를 유지하면서 단일 계좌로 실행한다. 상대강도 전략을 포함하지 않은 조합에는 시장 순위 선정을 강제하지 않는다.
3. **독립 전략 동시 운용:** 여섯 전략에 자금을 나누고 각 전략의 진입·청산·손절을 유지한다. 이는 전략별 보유 수량과 자금 관리가 필요한 별도 기능이다. 이번 기획의 1차 범위에 넣지 않는다.

이 기획은 2번을 중심으로 한다. 사용자에게 자동으로 더 유리한 전략을 골라 주는 기능이 아니라 결합 의도를 표현하고 검증하는 기능이다.

## 여섯 입력을 배치하는 예

사용 사례는 세 가지다.

- `20일 고가 돌파` 초안 선택 → 사용자가 지정한 종목으로 단독 테스트.
- `20일 고가 돌파 + SMA 골든크로스` 선택 조합 → 같은 종목에 두 조건 묶음을 적용. 결합 AND/OR와 공통 청산·손절을 확인한 후 테스트.
- 자동 생성된 `전체 토탈 · 6개` 선택 → 전체 구성과 충돌 항목을 검토한 후 테스트. 필요하면 포함할 전략을 줄여 별도 조합으로 저장.

토탈은 **모든 입력 전략을 구성 요소로 보존한 초안**이다. 자동 생성되었다고 해서 AND/OR나 공통 손절까지 확정된 실행 전략을 의미하지 않는다.

아래 OR 구성은 상대강도까지 포함해 여러 종목을 선정하는 토탈의 설명용 예제다. 특정 종목에 두 매매 전략을 적용하는 사용자에게 이 전체 구성을 강제하지 않으며, 결합 규칙도 사용자가 확정한 값이 아니다.

```text
대상 시장: KOSPI / KOSDAQ 중 사용자가 선택
    ↓
종목 선정: 주간 6개월 수익률 순위 + SMA200 필터
           필터와 순위의 적용 순서는 사용자가 선택
    ↓
신규 진입: 다음 그룹 중 하나 이상 충족 (OR 예제)
  A. 최근 20거래일 고가 상향 돌파
  B. 52주 신고가 경신
  C. SMA5가 SMA20을 상향 교차 AND SMA20 > SMA200
  D. 전일 종가 + 0.5 × 전일 ATR14 돌파
  E. SMA50이 SMA200을 상향 교차
    ↓
공통 청산·위험 관리: 사용자가 적용 범위와 결합 규칙 확정
    ↓
초기자금·보유 수량·비중·비용을 반영한 단일 계좌 결과
```

- 여섯 번째까지 모두 매수 OR 그룹에 넣는 것이 아니다. 상대강도 전략은 후보 종목 선정과 주간 조정 역할로 배치한다.
- C의 `SMA20 > SMA200`은 C 안에 남는다. 전체 진입의 공통 필터로 옮기려면 사용자에게 변경을 표시하고 확인받는다.
- 시장 선정의 `종가 > SMA200`과 C의 `SMA20 > SMA200`은 서로 다른 조건이다.
- 고가 돌파·교차 이벤트를 “이미 그 위에 있음” 상태로 바꾸지 않는다. 조건 기간이나 가격 기준도 자동 변경하지 않는다.
- 매도 후보는 10일 저가 이탈, SMA5/20 하향 교차, SMA50/200 하향 교차, 주간 순위 이탈이다. 이것을 전부 OR 청산으로 적용할지, 일부만 사용할지는 별도 선택이다.

## 원문 충돌의 처리

원문에 들어온 조건을 역할별로 옮긴 뒤 다음 항목을 해결해야 저장 가능한 통합 전략이 된다.

- 고정 손절 `-5%`, `-8%`, `-8~10%`: 공통 손절을 무엇으로 할지 질문한다. 가장 작은/큰 값, 평균값, -9% 등을 자동 채택하지 않는다. 고정 손절을 사용하지 않으려면 명시적으로 제외한다.
- 추적손절 `-20%`: 공통 적용 여부와 진입 후 최고 종가/일중 고가 기준을 확인한다.
- 고정 손절 또는 ATR 손절: 둘 중 하나를 선택하는지, 어느 하나라도 충족하면 청산하는지 확인한다. ATR 계산 방식과 진입 직전 완성 봉 사용 여부도 확인한다.
- 청산 조건: 원래 52주/ATR 전략의 “10일 저가 이탈”을 모든 보유분에 적용하면 전략 의미가 달라진다. 공통 청산으로 이동한 조건은 변경 목록에 표시한다.
- 주간 선정과 일별 진입: 후보 선정만으로 바로 매수할지, 추가 진입 조건을 충족해야 할지 확인한다. 이 기획의 통합 모드에서는 후자를 제안한다.
- 비중 조정: 기존 보유 종목을 매주 동일 비중으로 다시 맞출지, 신규 진입 때만 배분할지 명시한다.

원문 문장별로 `사용`, `공통 규칙으로 변경`, `제외 확인 필요`, `보완 필요` 상태와 연결된 조건 ID를 남긴다. 제외한 조건도 원문과 변경 사유를 저장하며 조용히 누락하지 않는다.

## 화면 흐름

### 입력과 조합

기존 `전략 원문`과 해석 버튼을 사용한다. 해석 결과 영역에 개별 초안들과 `전체 토탈 · N개` 카드를 함께 표시한다. 각각 독립적으로 선택·보완·편집·저장할 수 있다.

```text
전략 원문 → 조건 해석

개별 전략: [20일 돌파] [52주 신고가] [SMA 5/20] ...
전체 토탈: [입력한 6개 전략 전체 · 결합 규칙 보완 필요]
사용자 조합: 원하는 개별 전략을 체크 → [선택한 전략 조합]

선택한 초안 확인 → 실행 대상 종목·설정 지정 → 저장 버전 테스트
```

선택 조합은 2개 이상일 때 생성한다. 카드 이름에 포함 전략을 표시하고, 전체 토탈과 일부 조합을 구분한다. 원본 개별 초안과 저장 버전은 변경하지 않는다. 생성 시점의 조건을 복사하여 독립적으로 편집하며, 이후 원본 변경은 자동 반영하지 않고 재조합 여부를 선택하게 한다.

전체 토탈에 충돌·미지원 요소가 있어도 정상 개별 초안은 그대로 사용할 수 있다. 토탈의 문제로 전체 결과를 실패 처리하거나 개별 전략의 저장을 막지 않는다.

통합 화면은 다음 편집 영역을 제공한다.

1. 실행 대상: 특정 종목 지정 또는 여러 종목 선정. 상대강도가 포함되면 시장, 수익률 기간, 순위 수, 필터, 주간 계산일을 추가한다. 특정 종목 하나만 거래하더라도 시장 내 상대강도를 검사하려면 비교 대상 시장 자료가 필요하며, 단일 종목 자료만으로 순위를 계산하지 않는다.
2. 매수 조건: 그룹의 `모두 충족(AND)` / `하나 이상 충족(OR)`과 중첩 그룹 편집. 괄호가 보이는 문장 미리보기를 함께 표시한다.
3. 매도 조건: 공통 청산 그룹과 주간 순위 이탈 여부.
4. 위험 관리: 손절·ATR 손절·추적손절, 기준 가격과 적용 범위.
5. 자금 배분: 최대 보유 수, 동일 비중, 신규 배분/주간 재조정, 신호 부족 시 현금 유지.

오른쪽 또는 하단에는 `원문에서 달라진 내용`과 `해결할 질문`을 고정된 순서로 보여 준다. 충돌이 남으면 저장·실행을 막는다. 조건을 수정하면 확인 상태를 해제하고 다시 검증한다.

### 결과

기존 계좌 평가액·수익률·낙폭·거래 이력에 다음 근거를 추가한다.

- 상대강도를 사용한 경우 주간 후보 선정 이유와 미선정/이력 부족 이유.
- 어떤 매수 그룹이 충족되어 진입했는지. 동시에 충족한 그룹도 함께 기록한다.
- 선택 날짜·종목의 각 조건: 실제값, 기준값, 충족/불충족/준비 이력 부족.
- 선정되었지만 진입하지 않은 이유: 조건 미충족, 준비 이력 부족, 현금 부족, 보유 한도, 체결 자료 없음 등.
- 청산의 대표 사유와 함께 충족한 다른 사유. 같은 날 조건이 여러 개 발생해도 동일 보유분을 중복 매도하지 않는다.

관측된 조건별 진입 횟수는 설명용이다. 겹쳐 발생한 조건마다 같은 손익을 더해 “조건별 기여 수익률”로 표시하지 않는다. 기여도 비교는 조건을 뺀 별도 재실행을 해야 하는 후속 분석이다.

## 실행 의미 — 구현 전 확정할 제안

- 종목별 보유분은 하나로 관리한다. 여러 진입 그룹이 동시에 참이어도 한 번 진입한다. 진입 그룹별 별도 포지션이나 별도 손절은 1차 범위에서 제외한다.
- 특정 종목 조합은 지정한 종목만 매 거래일 평가한다. 상대강도 선정을 사용하는 조합에서는 주간 선정 목록을 다음 선정일까지 유지하고, 그 안의 미보유 종목의 신규 진입 조건을 검사한다. 선정됐지만 신호가 없으면 현금을 유지하며 순위 밖 종목으로 자동 대체하지 않는다.
- 진입 조건은 신규 포지션을 여는 조건이다. 기존 보유 종목의 진입 조건이 다시 거짓이 되었다는 이유만으로 청산하지 않는다. 청산은 명시적인 청산·위험 규칙을 따른다.
- 주간 동일 비중 재조정을 선택하면, 계속 보유할 종목과 신규 진입 신호가 난 종목에 한해 목표 수량을 만든다. 기존 보유분의 비중 조정과 신규 진입을 결과에서 구분한다. 최대 보유 수와 사용 가능한 현금 한도를 지킨다.
- 일별 손절·청산과 주간 선정·비중 조정이 같은 날이면 청산 대상을 먼저 제거하고 목표 수량을 계산한다. 같은 날 청산한 종목은 그날 재진입 대상에서 제외한다.
- 모든 조건과 위험 신호는 완성 일봉 종가 기준이다. 체결은 당일 종가 가정 또는 다음 거래일 시가 중 명시적으로 선택한다. 다음 시가 주문에 다음 날 종가·고가를 사용하지 않는다.
- 준비되지 않은 조건은 거짓과 별도로 기록한다. OR은 준비된 조건 하나가 참이면 통과할 수 있고, AND는 모든 필요한 조건이 참이어야 한다. 청산 지표의 준비 이력 부족이 고정 손절을 막으면 안 된다.
- 데이터의 과거 시장 구성·거래 캘린더와 저장된 원시 캔들을 사용한다. 현재 구성 종목을 과거 전체 시장으로 자동 소급하지 않는다.

**추가 매수·부분 매도가 있는 위험 관리 제안:** 고정 손절 기준은 현재 평균 매입가격, 추적 고점은 최초 진입부터 유지한 최고가, ATR 손절 가격은 최초 진입가격과 그 직전 ATR로 계산해 전량 청산까지 고정한다. 부분 매도는 고점/ATR 상태를 초기화하지 않는다. 전량 청산 후 새 진입에서 초기화한다. 이 규칙은 화면에서 명시적으로 설명·확인해야 하며, 다른 기준을 요구하면 구현 전에 계약을 바꾼다. 기존 버전 1~3의 위험 관리 의미는 바꾸지 않는다.

## 기술 방향

- 통합 전략 전용 형식 4를 제안한다. 형식 1·2·3을 자동 변환하거나 의미를 바꾸지 않는다.
- 기존 지표 조건을 말단으로 재사용하고 AND/OR 그룹을 중첩 가능한 구조로 확장한다. 각 조건·그룹에 안정적인 ID와 원문 출처를 둔다. 1차 한도는 중첩 3단계, 말단 조건 30개를 제안한다.
- 대상 선정, 진입 트리, 청산 트리, 공통 위험 관리, 자금 배분을 분리한 계약으로 검증한다. 중첩 깊이·빈 그룹·필수값·위험 정책 충돌을 모델 결과와 저장 요청에서 모두 검사한다.
- “통합해 줘”라는 원문만으로 결합 연산자와 공통 손절을 임의로 확정하지 않는다. Codex는 통합 초안과 보완 질문을 만들고, 계산·저장·실행은 기존처럼 Java가 담당한다. API 키 과금 경로를 추가하지 않는다.
- 기존 개별 해석/복수 초안 API 계약은 유지한다. 화면용 확장 응답은 개별 결과와 토탈 결과를 함께 반환하도록 설계한다. 한 번 추출한 개별 조건으로 토탈 구성과 충돌 목록을 만들고, 토탈을 보여 주기 위해 원문을 별도로 재해석하지 않는다. 선택 조합도 추출된 조건을 재사용하며 모호한 결합 규칙은 미정으로 남긴다. 자연어 보완 재해석만 추가 모델 호출을 사용하고, 검증·저장·실행·이력 조회는 사용하지 않는다.
- 지표 계산과 포트폴리오의 현금·수량·비용 계산을 재사용한다. 결합 규칙의 평가와 거래 결정은 전용 실행 경로로 구현하고, 공통 코드 추출 전후에 기존 결과가 같은지 검증한다.
- 실행 이력에 형식/엔진 버전, 통합 원문, 선택한 결합 규칙, 원문 변경 목록, 시장 자료, 캔들, 조건별 판정과 거래·계좌 결과를 함께 저장한다. 과거 이력은 현재 데이터나 현재 조합으로 다시 계산하지 않는다.

## 구현 순서와 완료 기준

1. **계약·검증:** 형식 4, 중첩 그룹, 공통 위험 관리, 조건 출처와 충돌 안내를 정의한다. 평면/중첩 AND·OR, 필수값 누락, 원문 조건 누락을 검증한다.
2. **실행 엔진:** 주간 후보 선정과 일별 신규 진입을 연결한다. 중복 신호, 손절 우선, 비중 조정, 평균 매입가·추적 고점·ATR 상태, 현금·비용, 종료 미체결을 검증한다.
3. **해석·화면:** 한 번의 원문 해석에서 개별 초안과 토탈을 함께 표시하고, 2개 이상 선택 조합·그룹 편집·충돌 해결·변경 확인·저장·실행·근거 조회를 연결한다.
4. **전체 검증:** 원래 여섯 문장에서 통합 초안 생성 → 충돌 보완 → 저장 버전 실행 → 결과·이력 조회까지 실제 흐름으로 확인한다. 기존 1~3과 분리 초안 기능도 회귀 검증한다.

대표 인수 시나리오:

- 원문에 독립 전략 6개를 입력하면 개별 초안 6개와 전체 토탈 초안 1개를 함께 보여 준다.
- 토탈에 손절 충돌이 남아 있어도 정상적인 20일 고가 돌파 개별 초안을 저장·실행할 수 있다.
- 20일 고가 돌파와 SMA 골든크로스만 선택한 조합을 특정 종목에 실행할 수 있고, 선택하지 않은 상대강도 시장 자료를 요구하지 않는다.
- 토탈·부분 조합 생성에 별도의 원문 해석 호출이 발생하지 않으며, 미정 AND/OR·손절은 자동 확정하지 않는다.

- `(20일 돌파 OR 52주 신고가) AND 공통 필터`에서 괄호와 필터 범위가 저장·실행·재조회 후에도 같다.
- A만 참, B만 참, 둘 다 참, 둘 다 거짓인 합성 데이터에서 예상 진입 수량과 횟수가 일치한다.
- 느린 지표가 준비되지 않았어도 준비된 OR 분기가 참이면 규칙대로 진입하고 준비 부족 근거를 남긴다.
- 주간 10개 후보 중 진입 조건을 만족한 3개만 신규 진입하며 나머지 몫은 설정대로 현금으로 남는다.
- 고정 손절·추적손절·지표 청산·순위 이탈이 겹쳐도 이중 청산과 같은 날 재진입이 없다.
- 부분 조정 후 평균 매입가·추적 고점·ATR 손절 상태가 확정한 계약대로 유지된다.
- 서로 다른 고정 손절률을 확정하지 않으면 저장되지 않고 어떤 원문에서 왔는지 안내한다.
- 원래 초안 6개와 기존 저장 버전은 통합 초안 생성에 의해 변경되지 않는다.
- 이력은 실행 당시 조건과 데이터에 고정되고, 미래 가격이나 현재 유니버스가 과거 판단에 섞이지 않는다.
